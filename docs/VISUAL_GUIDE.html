VISUAL USER GUIDE

Dremio Transform Studio

Step-by-step walkthrough with screenshots — from connecting to Dremio through building, scheduling, and monitoring production pipelines.

1

Connect to Dremio

Tell Transform Studio where your Dremio instance lives and how to authenticate.

On first launch the catalog tree will be empty. Click the gear icon ⚙ in the top toolbar — the tooltip reads "Connection Settings" — to open Settings.

Hover over the gear icon to confirm — tooltip reads "Connection Settings".
Connection tab — quick-setup presets for Self-hosted, Dremio Cloud US, and Dremio Cloud EU.
DeploymentAuth TypeFields
Self-hostedUsername / Passwordhost, port (9047), username, password
Dremio CloudPersonal Access Tokenapi.dremio.cloud, PAT token, Project ID

  1. Click ⚙ gear icon in the top toolbar.

  2. Click a Quick Setup preset (Self-hosted, Dremio Cloud US, or Dremio Cloud EU) to pre-fill the host.

  3. Enter your credentials and click Test Connection — look for the green success message.

  4. Click Save & Connect. The catalog tree populates on the left.

Create a Pipeline & Select a Source Table

Every pipeline starts with a source table from the Dremio catalog.

A new pipeline showing the Notes field, "Add to folder" button, and "Add tag" button at the top of the builder.
Click the pencil icon next to the pipeline name to rename it. Or double-click the name in the header.

  1. Click + New in the pipeline list or + New Pipeline in the toolbar.

  2. In the left catalog tree, expand a namespace and click a table name — it becomes the pipeline's source.

  3. Optionally add a description in the Notes field at the top of the builder.

  4. Click Add to folder to organise the pipeline, or Add tag to label it (e.g. finance, daily).

  5. Click the pencil / rename icon next to the pipeline name to give it a meaningful name.

💡
Tags & Folders — add free-form tags to any pipeline and group them into named folders. The pipeline list is filterable by tag, which makes it easy to manage dozens of pipelines.

Configure a Transform Step

Click any step card to open its configuration form in the CONFIG tab on the right.

CONFIG tab for "Remove Duplicates" — column checkboxes are auto-populated from the Dremio table schema. Every step has an optional Step Label and Notes field.
  • Column dropdowns are automatically populated from the upstream schema.
  • Use {{param_name}} in any text field to make it a pipeline parameter (see Parameters section).
  • Every step has an optional Step Label to override the default name shown on the card.
  • The optional Notes field adds a free-text annotation visible on the step card and searchable via ⌘K.
  • Click Remove step at the bottom of the config panel to delete the step.
6

Custom SQL Step

Drop into a full SQL editor when the visual transforms aren't enough.

Full-screen Custom SQL editor. The column list at the top shows available columns. The Template Library on the right lets you save and load reusable SQL snippets.
  • {input} — reference the upstream CTE in your FROM clause. Transform Studio substitutes the actual CTE alias at compile time.
  • Template Library — click + Save as Template to store a snippet. Search and click Load to insert it in any future pipeline.
  • Column names shown at the top are clickable — click to insert the name at the cursor position.
  • Click Apply to save the SQL back to the step, then Preview to see results.
⚠️
Dremio SQL notes: No SELECT * EXCEPT. Use lax mode for JSON paths: JSON_VALUE(col, 'lax $.field'). Use RAND() not RAND(seed).
7

Preview Results

See live query results from Dremio before writing anything.

Preview tab — row count, column count, and a scrollable data grid. Results come directly from Dremio.
SQL tab — the exact CTE chain Transform Studio compiled from your steps. Click Copy to use it elsewhere.

  1. Click Preview in the toolbar (or the blue ▶ Preview button bottom-right of the builder).

  2. Results appear in the bottom panel → Preview tab — scrollable grid with column headers.

  3. Click the SQL tab to inspect the generated CTE chain — great for debugging.

ℹ️
Preview is always read-only. It runs a SELECT — no data is written until you click Execute. Preview as many times as you like at no risk.

Set Output Mode & Execute

Choose how to materialise your pipeline, then write data to Dremio.

Output mode dropdown at the bottom of the builder — all six modes shown. Set an output table name first, then pick the mode.
Output ModeWhat it does
Preview onlySELECT only — nothing written. For development.
Create Table (CTAS)CREATE TABLE AS SELECT — creates or replaces a Dremio table.
Insert IntoINSERT INTO an existing table — appends new rows.
Create ViewCREATE OR REPLACE VDS — a virtual dataset, no data copy.
IncrementalAppend or merge only new rows since last run.
SCD Type 2Slowly changing dimension with history tracking.

  1. Set the Output Table name (e.g. MySpace.daily_sales).

  2. Choose the Output Mode from the dropdown.

  3. Click Execute in the toolbar. Transform Studio saves the pipeline first, then runs it.

  4. On success, a green banner reports the row count. Any configured Pipeline Tests run automatically.

Schedule a Pipeline

Run on a cron schedule with retry logic and optional SLA deadline alerting.

The CalendarClock icon in the toolbar — hover shows "Schedule Pipeline".
Schedule modal — quick presets, custom cron expression, retry slider (0–5 retries with exponential backoff), and SLA Deadline toggle.

  1. Click the CalendarClock icon in the toolbar (tooltip: "Schedule Pipeline").

  2. Choose a Quick Preset or enter a custom cron expression (e.g. 0 6 * * * = 6 AM daily).

  3. Set Retry on Failure — drag the slider to configure up to 5 retries with exponential backoff.

  4. Toggle SLA Deadline on and set a time (e.g. 08:00 UTC) — if the pipeline hasn't completed by that time, an alert fires via email or Slack.

  5. Click Create Schedule (or Save Schedule if updating).

ℹ️
Environments: The Default dropdown in the toolbar lets you switch between named Dremio connection profiles. All executions (manual and scheduled) use the active environment's credentials.
11

Pipeline Parameters

Make pipelines reusable by replacing hard-coded values with named parameters.

Params tab — the sliders icon in the right-panel tab bar. Click "+ Add" to define a parameter with a name, type, and default value.

  1. Open the Params tab (sliders icon ⊞ in the right-panel tab bar).

  2. Click + Add and define a parameter: name, type (text / number / date / boolean / dropdown), and default value.

  3. Use {{param_name}} in any step's text config field — Transform Studio substitutes the value at runtime.

  4. When running manually, a Run with Parameters modal lets you override defaults before execution.

  5. Scheduled runs use the default values. Webhook triggers can pass param_values in the request body.

💡
Example: Add a start_date parameter (type: date, default: 2024-01-01) and reference it in a Filter Rows step as order_date >= '{{start_date}}'. Now one pipeline handles any date range.
12

Webhooks

Trigger any pipeline from an external system using a secure per-pipeline URL.

Webhook tab — shows the unique trigger URL, a ready-to-use cURL example, and an Airflow / Python example. The token in the URL is the authentication.

Open the Webhook tab (link icon 🔗 in the right-panel tab bar). Each pipeline has a unique URL — POSTing to it triggers an execution. The token in the URL is the only authentication required.

ModeBehaviour
mode=async (default)Returns immediately with a job_id. Poll the status endpoint to check completion.
mode=syncWaits for the pipeline to finish and returns the result (row count, status, errors).

Pass param_values in the JSON body to override parameter defaults: {"param_values": {"start_date": "2024-06-01"}}

💡
Regenerate token: If a token is compromised, click the regenerate button in the Webhook tab to issue a new token. The old URL stops working immediately.
13

Pipeline Tests

Define data quality assertions that run automatically after every successful execute.

Tests tab (flask icon) — shows defined tests with column, assertion type, and severity. Click "+ Add Test" to define a new assertion. "Run Now" runs all tests against the current output table.
Test TypeWhat it checks
not_nullColumn has no NULL values
uniqueColumn has no duplicate values
row_count_betweenOutput row count is within min/max bounds
accepted_valuesAll values in a column are from an allowed list
relationshipsColumn values exist in a reference table (referential integrity)
custom_sqlA SQL query you write returns zero rows (i.e. no violations found)
  • Error severity — blocks the pipeline from being marked successful. Downstream pipelines that depend on this one will not run.
  • Warn severity — logs the failure but does not block.
  • Store failures — optionally write failing rows to a Dremio table for investigation (e.g. MySpace._failures_product_id_not_null).

Version History & Run Log

Every save creates a version. Every execution creates a run record.

HISTORY tab — every save creates a numbered version with a timestamp. Click Restore to revert to any prior state.
RUNS tab — all executions for this pipeline: status, row count, start time, and error messages.

The HISTORY tab tracks every save. Click Restore on any version to rewind the pipeline steps to that state — useful for rolling back a bad change. The RUNS tab tracks every execution (manual, scheduled, or webhook-triggered) with full status details.

Alerts

Custom SQL checks, pipeline health monitors, data quality alerts, and source freshness — all on a schedule.

New Alert modal — four alert types shown as selectable cards. Configure the SQL condition, schedule, and notification destination.
Alert TypeHow it works
Custom SQLRuns a SQL query; fires if any rows are returned (e.g. SELECT 1 FROM orders WHERE status='error').
Pipeline HealthFires if a specific pipeline failed in its last N runs.
Data QualityFires if a DQ monitor's score drops below its threshold.
Source FreshnessFires if MAX(timestamp_col) of a table is older than a configured threshold.

Notifications go to email and/or Slack (configure in Settings → Notifications). Click Run Now on any alert to test it immediately.

Data Quality Hub

Dedicated DQ workspace with monitors, scoring, scheduling, and 14 built-in rules.

DQ Hub Overview — stat cards (total monitors, avg score, passing, failing) and animated score rings per monitor. Click any monitor to see its rule results.
New Monitor wizard Step 1 — browse the catalog to pick the table to monitor. Steps 2 and 3 configure rules and schedule.

Click the DQ Hub button (🛡 DQ Hub) in the toolbar. Four sections:

  • Overview: Stat cards + monitor health grid with animated score rings.
  • Monitors: List all DQ monitors with score, last run, and controls.
  • History: Cross-monitor scan log — all scans newest first.
  • Rule Catalog: All 14 built-in rule types — click "Add to monitor" to quick-add.

DQ scores are a weighted average of rule pass rates. ≥ 90% green · 70–89% amber · < 70% red. Monitors alert via email/Slack when score drops below a configurable threshold.

dbt Compatibility

Export pipelines as a dbt project, or import any dbt project — no dbt installation required.

Import from dbt — drop a dbt project ZIP. Transform Studio resolves all Jinja ({{ ref() }}, {{ source() }}, {{ config() }}) without dbt installed.
A pipeline created by importing a dbt model — each model becomes a Custom SQL step. Dependencies are wired automatically from {{ ref() }} calls.
📦

Export to dbt

Click Export as dbt Project icon in toolbar. Downloads a ZIP with one .sql model per pipeline, sources.yml, schema.yml, and dbt_project.yml. Run with dbt run after editing profiles.yml.

⬆️

Import from dbt

Click Import from dbt icon in toolbar. Drop a ZIP — resolves {{ ref() }} → pipeline deps, maps materializations, converts schema.yml tests to pipeline tests. Preview models before confirming the import.

Seed a Table from CSV

Upload a CSV directly to Dremio as a new table — no SQL needed.

Seed Table from CSV — drop a CSV file (max 5,000 rows). Transform Studio infers column types and creates the Dremio table automatically.

  1. Click the Seed Table from CSV icon in the toolbar (tooltip: "Seed Table from CSV").

  2. Drag and drop a .csv file (UTF-8 or Latin-1, max 5,000 rows).

  3. Enter the destination table name in namespace.tablename format.

  4. Click Seed Table. The table appears in the catalog tree immediately.

⚠️
Destination: Target must be a Dremio Space (e.g. MySpace) or Iceberg source. Seeding into @username home spaces creates a VDS, not a physical table.

Stopping the App

The desktop installer includes a dedicated Quit button in the toolbar.

When running the desktop app (Mac .dmg or Windows .exe), the toolbar shows a ⏻ Quit button — the red power icon at the far right. Click it to gracefully shut down the embedded server and close the application.

ℹ️
Desktop only: The Quit button does not appear when running via Docker. It is intentionally hidden for shared-server deployments so that no browser user can accidentally stop a server that others are using. Docker users stop the container with docker compose down from the terminal.
✅
No data loss on quit: All pipelines, schedules, and settings are stored in the SQLite database on disk — quitting or restarting the app never deletes your work.
✦

Pro Tips

Power-user features worth knowing once you're comfortable with the basics.

🔍

Global Search ⌘K

Press ⌘K (Mac) or Ctrl+K to search all pipeline names, step configs, source tables, and notes instantly.

🏷️

Tags & Folders

Tag pipelines with free-form labels and group them into folders. Filter the sidebar by tag to find related pipelines fast.

🌐

Environments

The Default dropdown in the toolbar switches between named Dremio connections — dev, staging, prod. All runs use the active environment.

📋

Audit Log

Admins can see a full log of every create, save, execute, delete, share, schedule, and SLA breach — with user, timestamp, IP. CSV export included.

🤖

MCP Server

Built-in MCP server at /mcp/sse with 22 tools. Connect Claude, Cursor, or any AI agent to run, list, schedule, and inspect pipelines via natural language.

📁

Export Documentation

The download icon in the toolbar exports a self-contained HTML doc covering all pipelines — steps, parameters, schedules, tests — shareable without a login.

👤

Per-User Credentials

Each user can store their own Dremio PAT under User menu → My Dremio Credentials so queries run under their own Dremio identity.

💾

Backup & Restore

Settings → Storage → Download Backup saves your full SQLite database. Use Restore to migrate between machines or recover from issues.
